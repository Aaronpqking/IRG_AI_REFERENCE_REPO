# Durable principles — conditional design guidance
1. Resolve exact model/product identity before technical retrieval; document applicability is an independent explicit gate.
2. Preserve source authority by fact type: catalog/MySQL identity and merchant state differ from manufacturer technical PDFs; compatibility must be explicit.
3. Keep canonical evidence stable; derived lexical, dense, structural and contextual representations are rebuildable indexes, not ground truth.
4. Candidate match is not automatically complete evidence; owner, configuration, table headers/units, warnings and steps can require parent-child reconstruction.
5. Use bounded context selection and a versioned model-visible serialization contract; the final answer depends on what the model actually sees.
6. Evaluate sufficiency and response decision (answer, clarify, abstain), and validate citation against source and each claim.
7. Bind serving/evaluation source, corpus/index, config and prompt; preserve immutable holdouts and negative results.
8. Complexity must earn inclusion with new unseen **downstream** improvements net of latency, storage and maintenance costs.
These principles reflect accumulated project evidence and are not individually qualified release claims.
